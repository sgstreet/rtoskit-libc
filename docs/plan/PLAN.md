This is the source of truth for the project's goals, architecture and decisions.

## 1. Goals

1. A clean-room, ISO/IEC 9899:2024 (C23, N3220) compliant C standard library for
   deeply embedded systems. The normative reference is `docs/standard/library-7.pdf`
   (clause 7) and `docs/standard/annex-b.pdf` (library summary).
2. Implemented in C23 (`-std=c23`). All per-thread library state uses
   `thread_local` (`errno`, `strtok`, `rand`, the `asctime`/`gmtime`/`localtime`
   static buffers, `tmpnam`, ...).
3. A single, explicit **RTOS seam** (`__rtos_*` functions) through which the
   library gets locks, threads, the TLS setup, time, I/O, the heap and process
   exit. No other OS dependency.
4. Minimal conditional compilation. Variation (arch, port, feature flavours) is
   chosen by the **build system selecting files** and by **link-time
   binding**, not by `#if`.
5. libc-test validates every step of every phase. No step is done until libc-test
   has no regressions against the recorded baseline on every enabled
   architecture.
6. Built only with the build system in `tools/`.

### Phases

| Phase | Goal | Exit criterion |
|---|---|---|
| 1 | Compliant implementation | Every applicable libc-test test passes on x86_64 and all ARM targets. The header audit against Annex B is clean. |
| 2 | Size pass | The size baseline is reduced per target, and libc-test still passes in full. |
| 3 | Performance pass | The benchmark baseline is improved per target, libc-test still passes in full, and the size budget from Phase 2 holds. |
| 4 | Arm Optimized Routines comparison | rtoskit-libc is measured against Arm Optimized Routines (`string`, `math`, `fp`; https://github.com/ARM-software/optimized-routines) on every Arm board: code size, instruction counts and accuracy in one report, with the gaps it finds recorded as open questions or later steps. libc-test still passes in full and both size budgets hold. |

### Scope (decided)

**In scope (ISO C23 clause 7):** `<assert.h>` `<complex.h>` `<ctype.h>`
`<errno.h>` `<fenv.h>` `<float.h>` `<inttypes.h>` `<iso646.h>` `<limits.h>`
`<locale.h>` `<math.h>` `<setjmp.h>` `<signal.h>` `<stdalign.h>` `<stdarg.h>`
`<stdatomic.h>` `<stdbit.h>` `<stdbool.h>` `<stdckdint.h>` `<stddef.h>`
`<stdint.h>` `<stdio.h>` `<stdlib.h>` `<stdnoreturn.h>` `<string.h>`
`<tgmath.h>` `<threads.h>` `<time.h>`

**Out of scope:** `<wchar.h>`, `<wctype.h>`, `<uchar.h>`, POSIX extensions,
Annex K (bounds-checking interfaces), decimal floating point (`_Decimal*`, an
optional feature: `__STDC_IEC_60559_DFP__` is not defined).
The multibyte functions that `<stdlib.h>` itself declares (`mblen`, `mbtowc`,
`wctomb`, `mbstowcs`, `wcstombs`) are still required. They are implemented for
the "C" locale only (`MB_CUR_MAX == 1`), and `wchar_t` comes from `<stddef.h>`.

**Order:** libm is implemented **last** in Phase 1.

### Target matrix

| Target | `ARCH_CROSS` (D22) | Test board (`BOARD_TYPE`) | Core / ISA | `long double` | FPU | Role |
|---|---|---|---|---|---|---|

| `armv7e-m-dp` | `armv7e-m-dp` | `linux-armv7e-m-dp` | Cortex-M7 with the double-precision FPU (Thumb-2, DSP) | 64-bit | FPv5-D16, single + double (hard) | Phase 2 and 3 target |
| `armv8-m.main` | `armv8-m.main` | `linux-armv8-m.main` | Cortex-M33 (Thumb-2, DSP) | 64-bit | FPv5-SP (hard) | Phase 2 and 3 target |

The `linux-*` boards run the test binaries through `port/linux`, natively or
under `qemu-arm`. Real hardware boards (e.g. `pi-pico`, `pi-pico2`) with
`port/none` or `port/rtoskit` can be added as further `BOARD_TYPE` files.
The plan text uses the target names; build commands use the board and
`ARCH_CROSS` names.

RISC-V is not targeted for now. The layout allows it to be added as just
another `arch/` and toolchain file.

## 2. Decision log

Every decision gets an ID. Revisit a decision by adding a new entry that
supersedes it; do not edit history.

| ID | Decision | Rationale |
|---|---|---|
| D1 | **Clean-room implementation.** Other libcs (musl, picolibc, newlib, glibc, Bionic, FreeBSD, ARM optimized-routines, CORE-MATH, ...) are *studied* before writing any algorithm, but no code is copied or mechanically translated. | The user requires clean-room. Keeps the MPL-2.0 licensing unencumbered. |
| D2 | **Research before implementing.** Each non-trivial algorithm gets a note in `docs/research/<topic>.md`: the sources reviewed (with URLs), their trade-offs, the chosen approach, and its edge cases. Notes describe ideas in our own words and contain no copied code. | User requirement. It also records provenance as clean-room evidence. |
| D3 | **libc-test runs natively on a Linux "port".** `port/linux` implements the RTOS seam with raw Linux syscalls (no glibc). On x86_64 the test binaries run natively; ARM binaries run under `qemu-arm` (user mode). | It is fast, scriptable, and gives libc-test the process model it expects. |
| D4 | **The RTOS seam is link-time bound.** The library calls plain external functions `__rtos_*`, declared in `include/rtos/rtos-port.h` (an internal header installed for port authors). Each port supplies them in its own archive (`librtos-<port>.a`). There are no function-pointer tables and no `#ifdef RTOS_X`. Port-defined *types* (e.g. lock storage size) come from `port/<port>/include/rtos/rtos-port-types.h`, found through the include path. | It has zero runtime overhead, needs no conditional compilation, and keeps the seam explicit and auditable. |
| D5 | **Selection by files, not `#if`.** Arch overrides live in `arch/<arch>/src/<area>/<name>.{c,S}`. When an arch provides a file with the same stem as a generic `src/<area>/<name>.c`, the build uses the arch file instead. Arch-specific headers are found through `-I arch/<arch>/include` placed before `-I include`. | This is the user requirement to minimize conditional compilation. |
| D6 | **One external function per source file** (musl-style). Each `thread_local` state object is its own variable next to its only user, not a big shared TLS struct. | Archive members then pull in only what is used. With `-fdata-sections` unused `.tbss`/`.tdata` is dropped, so threads pay TLS only for features the image uses. It also makes arch overrides (D5) trivial. |
| D7 | *Proposed, needs confirmation:* build the x86_64 test configuration with **`-mlong-double-64`**, so `long double` matches the ARM targets (binary64). Everything, including libc-test, is compiled with the same flag and statically linked. | It avoids writing and maintaining a whole ld80 libm and printf/strtold path that no product target uses. libc-test's math tables select by `LDBL_MANT_DIG`, so the binary64 tables are used. If rejected, Phase 1 grows ld80 variants under `src/math/ld80/`. |
| D8 | **The library owns all headers**, including the freestanding ones (`<stddef.h>`, `<stdint.h>`, `<limits.h>`, `<float.h>`, `<stdarg.h>`, `<stdatomic.h>`, ...). They are built on compiler predefined macros (`__INT32_TYPE__`, `__FLT_MANT_DIG__`, `__builtin_va_list`, `__atomic_*`, ...). The library and its tests compile with `-nostdinc -ffreestanding`. | It gives one consistent header set across GCC and Clang. There is no leakage from host glibc headers. |
| D9 | **Toolchain floor: GCC ≥ 14 or Clang ≥ 19** (the first versions with usable `-std=c23`, `constexpr`, `typeof`, `[[attributes]]`, `nullptr`, `_BitInt`). On the Ubuntu 24.04 container use `apt install gcc-14` (GCC 13 rejects `-std=c23`). For ARM, use the `arm-none-eabi` 15.2 toolchain that `setup.mk` already sketches. | Required for the C23 target. |
| D10 | **The TLS model is static `local-exec`.** libc provides `__libc_tls_size`, `__libc_tls_align` and `__libc_tls_init(void *block)`, which copy `.tdata` and zero `.tbss` from linker symbols. The port allocates the per-thread block and sets the thread pointer (x86_64 `%fs`; ARM `__aeabi_read_tp`, provided by the port). | There is no dynamic loader on embedded targets. It is the cheapest correct `thread_local`. |
| D11 | **Heap:** libc owns `malloc` (a clean-room allocator, see the research step). It gets memory from `__rtos_heap_region()`/`__rtos_sbrk()` and is protected by a seam lock. An RTOS may replace `malloc` wholesale by linking its own definitions ahead of libc.a. | Deterministic behaviour matters on embedded systems, and replacing the allocator must stay possible. |
| D12 | **Size and speed flavours** are chosen per build without `#if`. Speed-oriented arch files live in `arch/<arch>/speed/...` and size-oriented ones in `arch/<arch>/size/...`. The build picks a flavour directory (`LIBC_FLAVOUR=size|speed`, default `size`). | It reconciles Phase 2 and Phase 3. Needs confirmation (see Q3). |
| D13 | **Feature trimming is link-time.** Expensive optional paths, such as floating point in `printf`/`scanf`, are reached through a symbol that the full variant defines and a small variant stubs out. The small variant lives in a separate archive (`libc-nofloat.a`) linked ahead of `libc.a`. It is never selected with `#if`. | This is the picolibc-style flavour idea, done at link time. It is a Phase 2 item. |
| D14 | **Tracking:** phase files plus a step ID per session. Each step lists its deliverables and its definition of done. Sessions update the checkboxes, the test baselines and the decision log, then commit. | The work spans many sessions. |
| D15 | **Headers are per target triple, not per multilib.** Every multilib of one GCC (e.g. all `arm-none-eabi` M-profile variants) shares one `include/` directory, so `arch/arm/include/` must be valid for all of them. Types such as `jmp_buf` are sized for the largest variant (with the VFP callee-saved registers: s16–s31 for single precision and d8–d15 for double precision are the same 64 bytes); `fenv_t` (FPSCR) is the same for all. Only `arch/<arch>/src/` (code) differs per multilib. | Phase 4 needs it: GCC multilib installs one sysroot `include/` and per-multilib `lib/<multidir>/`. Deciding this early stops Phases 1 to 3 from baking per-arch header differences in. |
| D16 | **The build can be driven from outside.** A caller (crosstool-NG) can build and install one multilib with `make ARCH_CROSS=<arch> CROSS_COMPILE=<prefix> MULTILIB_FLAGS='<flags>' MULTIDIR=<dir> PREFIX=<sysroot> install`, and install headers alone with `make install-headers`. | crosstool-NG needs headers before the final GCC, and then one libc build per multilib. |
| D17 | **Arch code comes from ordered layers.** Each `tools/makefiles/<arch>.mk` sets `ARCH_LAYERS`, an ordered list of `arch/<layer>/src` directories. For each source stem the first layer that has the file wins; otherwise the generic `src/` file is used. Layers are per ISA (`armv6-m`, `armv7e-m`, `armv8-m.main`) and per FPU (`fpv4-sp`, `fpv5-sp`, `fpv5-dp`). For example, `armv7e-m-dp` uses `armv7e-m-dp fpv5-dp fpv5-sp armv7e-m`. This extends D5. | It shares FPU-specific code between ISAs (the Cortex-M7 DP unit and FPv5 on v8-M) and ISA-specific code between FPU variants, without duplicating files and without `#if`. |
| D18 | **Support the Cortex-M double-precision FPU (FPv5-D16, e.g. Cortex-M7 with the DP unit)** as the arch `armv7e-m-dp` (`-march=armv7e-m+fp.dp -mfloat-abi=hard`, i.e. FPv5-D16; D24). On it, `double` operations are hardware; `float` and `double` both get FPv5 instructions (`VSQRT`, `VFMA`, `VRINT[ANPMZX]`, `VMAXNM`/`VMINNM`, `VCVT[ANPM]`) through the `fpv5-sp`/`fpv5-dp` layers. Note that FPv5-SP (Cortex-M33, and the M7 SP option) also has these instructions for `float`, but FPv4-SP (Cortex-M4F) does not. | User requirement. It needs no header changes (D15 holds: the register file and FPSCR are shared). |
| D19 | **Exception to the no-`#if` rule:** `<limits.h>` selects `CHAR_MIN`/`CHAR_MAX` with `#ifdef __CHAR_UNSIGNED__`. Plain `char` signedness is a compiler option with no predefined *value* macro, and the limits must be usable in `#if`. Further compiler-property selections in headers need their own entry. | There is no conditional-free way to express it. |
| D20 | **`<errno.h>` values follow the Linux numbering** (`EDOM` 33, `ERANGE` 34, `EILSEQ` 84, `EBADF` 9, ...). Seam functions return negated errno values, so `port/linux` passes kernel results through unchanged, and other ports map their own codes. | Simplest for the test port. The values are arbitrary otherwise. |
| D21 | **Build layout:** `src/`, `arch/` and `include/` are source pools with no `.mk` files. The `libc/` module compiles them (through `libc/subdir.mk` → `tools/makefiles/libc.mk`), and the `port/<port>/` modules select from their own `src/` and `arch/<layer>/src/` the same way. `BUILD_ROOT` and `INSTALL_ROOT` include `ARCH_CROSS` (`build/<arch>/<type>`, `images/<arch>/<type>`). Consumers (`example/`, `test/`) get the libc include and link flags from `tools/makefiles/libc-target.mk`, which each `<arch>.mk` includes. | It keeps one compile rule for layered selection (D5, D17), and lets several arches coexist in one tree. |
| D22 | **Build system usage follows the pi-pico conventions** (supersedes D5, D17 and D21). (1) Every source directory is a module with its own `<dir>.mk` (from `tools/templates/src-template.mk`) and compiles in place. Library code lives under `libc/<area>/` and `port/<port>/`, and private headers in `libc/internal/` (header-only, no `.mk`). (2) Arch variation lives in variant subdirectories named after the `ARCH_CROSS` toolchain file (`libc/tls/x86_64/`, `port/linux/armv8-m.main/`). The parent module selects them with `SUBDIRS := ${ARCH_CROSS}` (as `sys/sys.mk` does in pi-pico). Code shared between cores goes in a subdirectory named by a variable the toolchain file sets (e.g. `LIBC_FPU := fpv5-dp`, `SUBDIRS := ${ARCH_CROSS} ${LIBC_FPU}`). When a generic C function needs an arch override (Phase 2/3), the generic module's `subdir.mk` filters it out of `SRC`. (3) Archives are built by a parent module that lists its children in `TARGET_OBJ_LIBS` with `all: ${CURDIR}/libX.a` (`libc/libc.mk` → `libc.a`, `port/linux/linux.mk` → `librtos-linux.a`, like pi-pico `runtime.mk`). (4) Executables list the object directories they link in `TARGET_OBJ_LIBS` (e.g. `port/${RTOS_PORT} port/${RTOS_PORT}/${ARCH_CROSS}`). The toolchain file links `libc.a` from the build tree through `LDLIBS`, as pi-pico's toolchain file points at its build-tree picolibc. (5) A `BOARD_TYPE` file (`tools/makefiles/<board>.mk`) exports `ARCH_CROSS` and `RTOS_PORT`. The `ARCH_CROSS` file (`tools/makefiles/<arch>.mk`) holds the toolchain and all flags, including `LIBC_CFLAGS` for library modules. The top-level `Makefile` loops over `BOARDS` × `BUILDS` into `build/<board>/<build-type>`. (6) Builds always run from the project root. | Required by the user: the build system in `tools/` must be used the way pi-pico uses it. |
| D23 | **Tests run with `make check`** (amends D22 (6)): the top-level `Makefile` builds, then runs `test/unit/run-unit` on `${BUILD_ROOT}/test/unit` for every board and build type. libc-test joins the same target in P1.02. There is no `tools/test-runner`. | User direction. |
| D24 | **`ARCH_CROSS` toolchain files and variant subdirectories are named after the architecture, not a core** (amends D22): `x86_64`, `armv6-m`, `armv7e-m`, `armv7e-m-dp`, `armv8-m.main`, with test boards `linux-<arch>`. The ARM toolchain files select the target with `-march` plus extensions (e.g. `armv7e-m+fp`, `armv7e-m+fp.dp`, `armv8-m.main+fp+dsp`) and `-mfloat-abi`, never `-mcpu`. That way the library is not tuned for one core, and the names match the GCC multilib directories used in Phase 4. | User direction. |
| D25 | **Lowercase everywhere unless the standard requires uppercase.** Applies to our identifiers, constants (as `static constexpr`, not macros), include guards (`__<name>_h`), file names (`_Exit` is in `_exit.c`) and test output. The exceptions are standard-mandated names (`_Exit`, `FILE`, the limit macros, `E*` errno macros per C23 7.5p4) and compiler/toolchain names (`__INT32_TYPE__`, `.note.GNU-stack`). This refines D6, which says the file is named after its function. | User direction. |
| D26 | **Linux kernel coding style, as in pi-pico** (supersedes D25 for macros and include guards): lower-case identifiers and file names; `ALL_CAPS` macros and enum constants (`__LINUX_SYS_WRITE`, `__LIBC_TCB_ALIGN`); include guards `_NAME_H` closed with `#endif /* _NAME_H */`; `/* */` comments only; `while (true)`; no alignment padding; no new typedefs beyond those the standard requires; `extern` declarations only in headers. `tools/clang-format` stays authoritative for layout. From D25, the lowercase file names (`_exit.c`) and the lowercase test output remain. | User direction. |
| D27 | **libc-test harness** (P1.02): `test/libc-test/manifest.txt` drives the build; each suite module (`test/libc-test/{api,functional,math,regression}`) includes the shared fragment `tools/makefiles/libc-test.mk`, which builds one ELF per `run` test straight from the submodule sources with our headers, the shim and the port objects. libc-test's warning set applies without `-Werror` (the api tests keep `-pedantic-errors -Werror`). `test/libc-test/shim/include/test.h` replaces libc-test's `test.h` (which needs `<unistd.h>`), and `t_printf` writes through `__rtos_write`. There is no `runtest`: `test/libc-test/run` applies the timeout and `TARGET_RUNNER`, writes `results.txt`, and fails on PASS→non-PASS and on failures missing from `expected/<board>.txt`; `make check LIBC_TEST_UPDATE=1` records improvements only. `api/main` has status `harness`. Executables also relink when `libc.a` changes (`EXTRA_ELF_DEPS` in the toolchain file). | Keeps the tools build system and avoids fork, which ports such as `port/none` cannot provide. |
| D28 | **Formatted-output engine** (P1.02, `docs/research/printf-engine.md`): one internal engine `__libc_format()` writes in chunks to a `struct __libc_format_sink` (buffer sinks now, `FILE` sinks in P1.09); the length modifier is kept as an enum so `va_arg` and `%n` use the exact type; floats go through the single replaceable symbol `__libc_format_float()` (stub until P1.08, D13). No positional `%n$` (POSIX). `%p` prints `0x` plus lowercase hex (`0x0` for null); `%s` of a null pointer prints `(null)`; `%lc`/`%ls` fail with `EILSEQ` (wide characters are out of scope); an unsupported `wN`, an invalid specification or decimal-float modifiers fail with `EINVAL`; results above `INT_MAX` fail with `EOVERFLOW`, checked before each field is written. `EINVAL` (22) and `EOVERFLOW` (75) join `<errno.h>` with Linux values (D20). | Standard text (C23 7.23.6.1) plus the reviewed engines; one engine for every destination keeps the size down. |
| D29 | **Executables declare the library dependency themselves** (amends D27): every executable module sets `EXTRA_ELF_DEPS := ${BUILD_ROOT}/libc/libc.a`, including the libc-test suite modules, instead of the toolchain file appending it. | User direction; keeps toolchain files free of module dependencies. |
| D30 | **String, character and bit utilities** (P1.03, `docs/research/string-ctype-stdbit.md`): word-at-a-time `strlen`/`memchr`/`strchr` (via `__libc_strchrnul`)/`memset` and co-aligned `memcpy`/`memmove`, reading only aligned `uintptr_t` words through `__builtin_memcpy` (`libc/internal/word.h`), byte loops elsewhere until P3.02; Two-Way `strstr`; 256-bit sets for `strspn`/`strcspn`; the C23 const-preserving search macros select with `_Generic(0 ? (p) : (void *)1, ...)` and the library defines those functions with parenthesised names; `strerror` is a `switch`; `<ctype.h>` is table-free and "C"-locale only; `assert` calls `__libc_assert_fail` (reserved-name rule, instead of the plan's `__assert_fail`) through a one-`bool`-parameter helper so `assert()` and `assert(1, 1)` are diagnosed; `<stdbit.h>` generic macros and all 70 typed functions use GCC 14's `__builtin_stdc_*`, `<stdckdint.h>` uses `__builtin_*_overflow`, and the endianness macros come from `__BYTE_ORDER__`. Unit tests build with `-fno-builtin` so they exercise the library rather than compiler folding. | Standard text plus the reviewed libcs; smallest generic code that is correct everywhere, with speed left to P3. |
| D31 | **Allocator and the heap/lock seam** (P1.04, `docs/research/malloc.md`; refines D11): a clean-room TLSF allocator (O(1) `malloc`/`free`, 16 second-level lists, payloads aligned to `2 * sizeof(size_t)`, one word of overhead per used block, control block carved from the largest region, `__libc_malloc_check()` for tests). Heap seam: `bool __rtos_heap_region(index, &base, &size)`, called until false at the first allocation (≤ 8 fixed regions), not `__rtos_sbrk`. Lock seam: opaque port-defined `struct __rtos_lock`, recursive `__rtos_lock_acquire/release`, `__rtos_lock_create/destroy` for run-time locks, and statically allocated locks named by libc and defined by the port (`__rtos_malloc_lock` now), so `libc.a` never depends on a port's lock size (this replaces the port-defined lock type header that D4 sketched). `port/none`: no-op locks and one heap region between the weak `__rtos_none_heap_start`/`__rtos_none_heap_end` linker symbols; `port/linux`: a 64 MiB `MAP_NORESERVE` region and depth-checking single-thread locks until P1.12. `malloc(0)` and `realloc(p, 0)` give a unique minimum block; failures set `ENOMEM` (12). | Deterministic timing and bounded fragmentation suit an RTOS; fixed regions match MCU memory maps; opaque locks keep one library per target. |
| D32 | **Two allocators, chosen at build time** (amends D31; `docs/research/malloc.md`): `libc/malloc/nano` (the default: first fit over an address-ordered free list with merging, written from the design of picolibc's allocator, 838 B of Thumb-2 for the full set on armv6-m) and `libc/malloc/tlsf` (O(1), 1532 B). The board file sets `LIBC_MALLOC ?= nano`; `make LIBC_MALLOC=tlsf` overrides it. Both variants are always built and `libc.a` takes `libc/malloc/${LIBC_MALLOC}` (a variant subdirectory, D22, no `#if`); `libc/malloc` holds the shared `calloc`, `free_sized`, `free_aligned_sized`. `test/unit/malloc` links one executable per variant so `make check` tests both. Changing `LIBC_MALLOC` in an existing build tree needs `make clean`, since archives are updated in place. | The user wants the small allocator by default and a choice; TLSF stays for bounded-time systems. |
| D33 | **`<stdlib.h>` part 2, `<inttypes.h>`, `<setjmp.h>`, `<signal.h>`** (P1.05, `docs/research/stdlib-part2.md`): one `__libc_strtoint()` core for the `strtol`/`strtoimax` family (C23 `0b` prefix, `EINVAL` for a bad base); heapsort `qsort` (smallest, O(n log n) worst case, no recursion; a speed flavour may follow in P3); `bsearch` with the const-preserving generic macro; `rand` is PCG32 with `thread_local` state and `RAND_MAX` 0x7fffffff; `atexit`/`at_quick_exit` use fixed 32-entry tables under the new seam lock `__rtos_atexit_lock`; `exit` runs the handlers then `.fini_array`; new seam functions `__rtos_getenv` and `__rtos_system`; multibyte functions for a single-byte "C" locale mapping bytes to the same wide value; `<inttypes.h>` `PRI`/`SCN` macros built on the C23 `wN`/`wfN` modifiers (`t` for `PTR`, asserted equal to `ptrdiff_t`), so the header has no per-target length letters; `jmp_buf` sized by one expression (`10 * sizeof(void *) + 64` bytes) that fits x86_64 and Arm, x86_64 `setjmp`/`longjmp` in `libc/setjmp/x86_64/`; software `signal`/`raise` with handler reset and default actions `__rtos_abort` (SIGABRT) or `_Exit(128 + sig)`. `call_once`/`once_flag` (also in `<stdlib.h>` in C23) wait for P1.12, `wcstoimax`/`wcstoumax` are out of scope (wide characters). | Standard text plus the reviewed libcs; small code, no `#if`, one header set per triple (D15). |

| D95 | **The size comparison with AOR** (P4.04, `docs/size/phase-4.md`). `size-report aor` measures what each AOR entry point that a board's programs use adds to an empty program (`tools/aor/size-main.c`, linked alone and with the routine forced in by `-u`, through `aor-build`'s `link()`). | D96 | **The toolchain integration leaves the phase plan** (supersedes D91's Phase 5). | D97 | **The accuracy comparison with AOR** (P4.05, `docs/research/optimized-routines.md`, `tools/scripts/aor-accuracy`). A host program calls our x86_64 functions (`libc.a` with every symbol prefixed `rt_`) and AOR's (entry points renamed `aor_`) and measures both against MPFR at 200 bits. Float functions are checked over all 2^32 arguments: every argument where the two libraries differ, and 1 in 16 where they agree. Doubles and `powf` are sampled, the three directed rounding modes are sampled, and special arguments are checked with their exception flags. Arm targets are sampled under qemu and measured on the host. `libmpfr-dev` is a host-only dependency of this test; nothing ships with it. The run found 8 float arguments that our functions round incorrectly, which contradicts D47's "correctly rounded". They are misrounded on every core, as P4.06 found (Q19). | Exhaustive float checks are the only way to back a correct-rounding claim; checking every disagreement plus a sample of agreements keeps a run to about 5 minutes per function. |
| D98 | **Correctly rounded float functions on the double path** (answers Q19; `docs/research/float-hard-cases.md`). On x86_64 and armv7e-m-dp every unary float function is its double function rounded to float (D45, D47). Where the exact value lies within a double ulp of a float halfway point, that second rounding can go the wrong way. An exhaustive search of the 36 transcendental unary float functions over all 2^32 arguments (`tools/scripts/float-hard-cases`, `tools/libm/float_hard_cases.c`, against MPFR) found 49 such arguments in 18 functions. In every one, the double result is exactly a float halfway point. Each function now passes its double result, its argument and a table of its hard cases (argument and correctly rounded result, 8 bytes each) to `__libc_float_round` (`internal/math.h`). An inline test on the double's low 29 bits sends only a result within 256 double ulps of a halfway point to the shared out-of-line lookup `__libc_float_case`. That lookup nudges a matching case's result toward the exact value, whose side the double result gives, so every rounding direction and inexact come out right. Double rounding cannot go wrong in a directed mode, and the search confirms this. The build's `-std=c23` (no FP contraction) makes the armv7e-m-dp double results identical to x86_64's, and `test/unit/float_hard` checks the 49 cases in all four directions on both. Cost: +5 to +9 instructions per call in the 18 functions (+0.6–3.1 % on x86_64, +1.1–5.9 % on armv7e-m-dp; new benchmark baselines), and +352 bytes in armv7e-m-dp `math-float` (64 bytes left in its size budget). The soft-float cores do not use these wrappers: their float-float layer (D57) has its own documented allowance (Q26). The binary float functions (`powf`, `atan2f`, `hypotf` and the like) cannot be searched exhaustively and remain sampled. | Exhaustive search is the only way to back a correct-rounding claim for float, and once the hard cases are known a lookup gated by an integer test costs far less than a more precise evaluation of every argument. |
| D99 | **Our own double-precision helpers on the single-precision FPUs** (answers Q24 for armv7e-m and armv8-m.main; `docs/research/softdouble.md`). A new libm layer, `soft-dp` (D46), on both cores, replaces every libgcc helper the compiler calls for double arithmetic and conversions; no libgcc floating-point member is linked any more. Only round to nearest, no flags (D44). The hot helpers are Thumb-2 assembly, complete with zeros, subnormals, infinities and NaN: `__aeabi_dadd`/`__aeabi_dsub` (operands ordered by magnitude, b shifted into three words with a sticky bit, a one-place or CLZ normalisation, exact subnormal results), `__aeabi_dmul` (UMULL/UMLAL/UMAAL, subnormals normalised, underflow rounded once on the subnormal grid), `__aeabi_d2f`, `__aeabi_f2d`, `__aeabi_d2iz`, `__aeabi_d2uiz`, `__aeabi_l2d` and `__aeabi_ul2d`. A first all-C version was correct but twice as slow as libgcc's assembly at `-Os`. The rest is C: `__aeabi_ddiv` (base-2^18 long division, each digit estimated from a single-precision reciprocal and corrected by the exact remainder), the comparisons (one shared ordering; `dcmpun` tests NaN directly because every `isnan` calls it), `i2d`/`ui2d`, the truncating 64-bit conversions, and `d2f` outside float's normal range. The helpers use the base calling convention (`pcs("aapcs")`, RTABI 4.1.1) and are weak, so a libgcc member that libgcc's own complex helpers pull in overrides them instead of clashing. Out-of-range float-to-integer conversions saturate as `VCVT` does. The step found a defect in libgcc's `__aeabi_dadd`/`dsub` on both cores: an effective subtraction across more than one binade whose result drops a binade is off by one ulp (4 of 60,000 test cases). `test/unit/softdp` hashes 30,000 cases of every operation on every board against the value x86_64's hardware fixes; it checks the layer's C and the C models of the assembly (`reference_add.c`, `reference_multiply.c`) against the hardware on x86_64, and the assembly against the models on the soft-dp cores. Speed (instructions per operation, both flavours, both cores): `dadd` 63.9 → 55.2, `dsub` 67.3 → 58.1, `dmul` 57.6 → 54.0, `ddiv` 583 → 174, `dcmp` 48.9 → 43.9, `i2d` 40.9 → 21.6, `l2d` 48.6 → 30.1, `d2l` 178 → 44.9, `f2l` 141 → 27.4; the double libm functions 15 % fewer instructions on the geometric mean (up to 47 %, `cbrt`; `sqrt` and `fmod` +0.1–0.3 %, within noise), `strtod` up to 30 % (release) and 51 % (speed) fewer, `sscanf("%lf")` 13–18 % fewer. Accepted: `fmod` latency +4.3 % (the benchmark's `x + y * 0.0` dependency costs about one ordinary addition through the zero paths, where libgcc's are shorter; `fmod` itself and its throughput are unchanged). Size: `math-mix` −156 bytes and `hello-printf-float` −668 (armv7e-m), −156 and −660 (armv8-m.main). | A correctness defect, 2–6× slower division and 64-bit conversions, and 1.6–1.9 KB per 64-bit conversion were libgcc's; the replacement is smaller and at least as fast in every case but one benchmark artefact. |
| D100 | **The soft-dp helpers are strong, and the layer defines libgcc's callers of them** (supersedes D99's weak definitions). Weak helpers turned a clash with libgcc into a silent substitution. libgcc's `__muldc3`, `__divdc3`, `__divsc3` and `__powidf2` call the double helpers, and GNU ld resolves those calls while it scans libgcc. So a complex multiplication or `__builtin_powi` linked libgcc's double objects (its misrounding addition included) beside ours, and a complex division with strong helpers failed with a duplicate `__aeabi_dcmpgt`. Every helper is now a strong global symbol, and the `soft-dp` layer defines those four from C23 Annex G.5.2. Multiplication recovers infinite results when both parts are NaN; double division scales the divisor by `logb`/`scalbn` and recovers the infinity and zero cases; float division is computed in double; `powi` squares. `__mulsc3` stays libgcc's (single-precision FPU arithmetic, no double helper). `test/unit/complex_ops` checks them on every board. A program that reaches a libgcc helper the layer lacks (the fixed-point conversions, the GNU-named `__adddf3` family) now links libgcc's object or fails with a duplicate symbol, rather than silently mixing. | The user's choice: a clash should be a link error to fix, never a silent substitution of a libgcc helper known to misround. |
| D101 | **The soft-dp comparisons in Thumb-2 assembly** (amends D99; `docs/research/softdouble.md`). `__libc_softdouble_compare` is now a hidden assembly routine. It sets the flags as `CMP` would for two ordered integers: Z for equal, C clear for less, and C set with Z clear for unordered, which none of the callers' conditions reads as true. It touches only ip. Each operand costs one compare for an exponent field of 2047 before any NaN test. Same signs compare as unsigned 64-bit integers, reversed for two negatives; only opposite signs test for two zeros. `__aeabi_dcmp{lt,le,eq}` are a call and one conditional move; `gt` and `ge` exchange the operands first. `__aeabi_dcmpun` stays C. The C ordering becomes the test's model (`test/unit/softdp/reference_compare.c`), checked against the hardware on x86_64; the soft-dp cores check all six predicates against it. `dcmp` 43.9 → 28.9 instructions (libgcc 48.9, AOR 20.2). The double libm is 0.8–2.2 % faster on 56 cases, both flavours, both cores, with nothing slower. Size: `math-mix` +24 bytes, the operand exchange in `gt` and `ge`. | The comparisons run several times in every libm call; the shared flag-setting routine keeps the size near the C version's. |
| D102 | **No libgcc object may replace one of the library's symbols, and `make check` proves it** (amends D85, D99, D100; `docs/research/softdouble.md`). `tools/scripts/libgcc-check` runs last in `make check`: it reads every link map of the configuration and fails when a program includes a libgcc member that defines a global symbol some `libc*.a` also defines. Strong symbols (D100) only turn a clash into an error when both definitions are linked; a libgcc helper whose callee only libgcc defines is resolved inside libgcc while the linker scans it, and can bring a libgcc copy of one of our helpers in first. The first run found exactly that on Armv6-M (`bench-stdio`, `bench-strto`): libgcc's `__aeabi_d2lz` (`_fixdfdi`) calls `__fixunsdfdi`, which calls `__fixunsdfsi`, which subtracts in floating point, so libgcc's `subdf3.o` (1444 bytes, its own `__aeabi_dadd`) replaced D85's. A new libm layer, `soft-int`, shared by the nofp and soft-dp cores, holds the conversions to 64-bit integers in C (`__aeabi_d2lz`, `d2ulz`, `f2lz`, `f2ulz`, moved from soft-dp); the nofp layer adds `__aeabi_d2uiz` and `__aeabi_f2uiz`. `softdouble.h` moves to `libc/internal/`. After the change no program in the 18 configurations links such a member. Armv6-M: `libc.a` +618 bytes, no reference image changes; `d2l` 696 → 62.5 and `f2l` 689 → 45.4 instructions (the other faster cases are the benchmarks' own conversions). armv7e-m and armv8-m.main are unchanged. The long comparison of the soft-dp layer is now reproducible: `softdp.elf [iterations [float-stride]]` and `tools/scripts/softdp-diff`, which by default runs 100 million cases and every float through `f2d` (x86_64 against the hardware; armv7e-m and armv8-m.main assembly against the models under qemu). Its first run passed with no difference: x86_64 in 2 minutes, armv7e-m and armv8-m.main in 28 minutes each. The archives collect their members by wildcard from the build tree, so a source moved out of a module leaves its old object in `libc.a` until `make clean`; a fresh checkout is unaffected. | D100 made a clash an error only when both copies are linked; a check over the link maps catches the substitution that strong symbols cannot, and the long runs that D99 and D101 cite should be repeatable. |
| D103 | **The heap stays `__rtos_heap_region`; an `sbrk`-backed RTOS takes region 0 from its break** (confirms D31; `docs/research/malloc.md`, "Growing with sbrk, evaluated"). All three allocators were rebuilt to grow on demand through an `__rtos_sbrk` seam (whole-stride growth, exact in place, used bridge chunks over memory another `sbrk` user took, requests bounded by `PTRDIFF_MAX / 4`, a static TLSF control block). It passed every check and mutant, and after tuning was 0.5–3.3 % faster on Arm, but it cost 68–76 bytes in each malloc reference image and 12 bytes of RAM, gave up the last large allocations of a fixed heap (or 40–50 bytes more to avoid that), made allocation call into the port at any time, and moved disjoint-memory handling into the port. By the user's choice the region seam stays, and a port whose RTOS owns the heap through `sbrk` (pi-pico's `sys/sbrk.c`) implements `__rtos_heap_region` by taking one block from that `sbrk` at index 0, at the first allocation: everything up to the heap's end, or all but a reserve for the RTOS's other `sbrk` users, which keep working above it. The `sbrk` implementation is kept on the branch `claude/sbrk-allocators` (fa6bbe1). | The sharing an `sbrk` heap needs is met at the port with no libc change, and the regions stay smaller, deterministic and able to use the whole heap. |
| D104 | **`.preinit_array` belongs to the port** (amends D10; `docs/research/tls-and-startup.md`, `include/rtos/rtos-port.h`). `__libc_start_main` runs only `.init_array`, then `main` and `exit`. The port's startup runs `.preinit_array` (bounds `__preinit_array_start`/`__preinit_array_end` from the default linker scripts, declared in `rtos-port.h`) once the initial thread's TLS is in place and before calling `__libc_start_main`. Neither C nor the compilers require the table: C23 only asks that static objects be initialised before `main`, and GCC and Clang put constructors in `.init_array`; `.preinit_array` is an ELF gABI convention that newlib, picolibc, glibc and musl honour at startup. Both ports run it, so code that follows the convention is unaffected. `test/unit/startup` checks the order (preinit hook, constructor, `main`, each once, `errno` usable in the hook) through the Linux port, and `test/unit/none` checks that `__rtos_none_start` runs it once with the TLS in place; both catch a missing run and a double run. | An RTOS can keep early hooks there and walk them itself (pi-pico's `PREINIT_*` tiers run from its own `_start`, before the scheduler); if libc also ran the table, every hook would run twice. |

## 4. The RTOS seam (contract sketch)

The exact signatures are finalised in step P1.01 (bootstrap), P1.04 (heap, locks), P1.09 (I/O), P1.11 (time) and P1.12 (threads).
All the functions are `extern`, have the prefix `__rtos_`, and are implemented by
exactly one port.

| Group | Functions (draft) | Used by |
|---|---|---|
| Process | `__rtos_exit(int)` `[[noreturn]]`, `__rtos_abort(void)` `[[noreturn]]` | `exit`, `_Exit`, `quick_exit`, `abort` |
| TLS | the port calls `__libc_tls_init()`; the port provides the thread pointer (`__aeabi_read_tp` on ARM, `%fs` on x86_64) | `thread_local` |
| Locks | `__rtos_lock_acquire/release(struct __rtos_lock *)` (recursive, opaque port type), `__rtos_lock_create/destroy`, and statically allocated named locks the port defines (`__rtos_malloc_lock`, `__rtos_atexit_lock`, `__rtos_stdin/stdout/stderr_lock`, `__rtos_stdio_lock`; more join with their steps) — final in P1.04 (D31) | malloc, stdio, atexit, `getenv`, time zone state |
| Threads | `__rtos_thread_create/exit/join/detach/self/yield/sleep` (opaque `struct __rtos_thread`), `__rtos_futex_wait/wake`, and for the `__atomic_*` library `__rtos_atomic_cas` and `__rtos_atomic_enter/exit` — final in P1.12 (D43) | `<threads.h>`, `<stdatomic.h>` library calls |
| Time | `__rtos_clock_gettime(int base, struct timespec *)`, `__rtos_clock_getres(int base, struct timespec *)` (`clock` uses `TIME_ACTIVE`, D42) | `time`, `timespec_get(res)`, `clock`, `thrd_sleep` |
| I/O | `__rtos_read/write(int handle, ...)`, `int __rtos_open(const char *, unsigned int flags)` (`__RTOS_OPEN_READ/WRITE/APPEND/CREATE/TRUNCATE/EXCLUSIVE/TEMPORARY`), `__rtos_close`, `long long __rtos_seek(int, long long, int whence)`, `__rtos_remove`, `__rtos_rename`, `__rtos_tmpname(char *, size_t, unsigned int index)`; negated errno on failure; a port with no file system implements only the std streams and returns `-ENOSYS` — final in P1.09 (D40) | `<stdio.h>` |
| Heap | `bool __rtos_heap_region(unsigned int index, void **base, size_t *size)`, called for index 0, 1, ... until false — final in P1.04 (D31) | `malloc` |
| Env | `char *__rtos_getenv(const char *)`, `int __rtos_system(const char *)` — final in P1.05 (D33) | `getenv`, `system` |

user-replaceable byte sink. That way a bare-metal image works with no RTOS at all.

## 5. Test strategy

- **libc-test** (`third-party/libc-test`, pinned at commit
  `7b95dfa5f5d5ca4d949221e0228ccc290bacc14e`). It is the main gate.
  - `test/libc-test/manifest.txt` lists every libc-test source with a status of
    `run`, `skip:<reason>` (POSIX-only, wide characters, fork, ...) or
    `pending:<step>` (not implemented yet).
  - `test/libc-test/shim/` replaces libc-test's POSIX-dependent `src/common`
    pieces (for example `t_printf` built on `write`, and `runtest` built on
    fork/exec) with ISO/port equivalents. This is test-only code.
  - The runner `test/libc-test/run` runs each test binary with a timeout (under
    `qemu-arm -cpu max` for ARM, D36) and writes `build/<board>/<type>/test/libc-test/results.txt`.
  - `test/libc-test/expected/<board>.txt` holds the committed baseline. The libc-test runner
    fails on any PASS→FAIL regression and reports FAIL→PASS improvements. A
    step updates the baseline only to record improvements.
  - `src/api` tests (compile-only declaration checks) are curated to their ISO subset.
- **test/unit**: our own tests for things libc-test misses: C23 additions
  (`<stdbit.h>`, `<stdckdint.h>`, `memset_explicit`, `strfromd`, `timegm`,
  `free_sized`, ...), `<threads.h>`, per-thread `errno` and state, the seam
  contract, and `port/none`.
- **Benchmarks** (phase 3, D72): `test/bench/` programs measured by
  `tools/scripts/bench-runner` under an instruction-counting qemu; `make bench`
  compares with `docs/perf/baseline-<arch>.json` and fails on regressions.
- **Header audit** (P1.17): a generated check that every identifier and macro in
  Annex B is declared with the right type, and that every `__STDC_VERSION_*_H__` is
  `202311L`.
- **qemu-user caveat:** `qemu-arm -cpu max` runs M-profile *instruction subsets* on an
  A-profile CPU model (D36). That is fine for libc code (no system registers), but
  ports must not use M-profile-only instructions in the Linux test port, and qemu
  does not reject instructions outside the selected architecture (the compiler and
  assembler `-march` do). An optional semihosted `qemu-system-arm` (mps2-an385/an505)
  gate can be added later.
